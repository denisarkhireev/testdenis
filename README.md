# Domino

Сетевая браузерная игра в домино для двоих. TypeScript-монорепо: сервер на Node.js + Socket.IO — источник истины, клиент на React + Vite, общие типы и правила — в `shared`.

## Требования

- Node.js 22 (`nvm use` — версия берётся из `.nvmrc`)
- npm ≥ 10

## Быстрый старт

```bash
npm ci
npm run dev
```

Откройте <http://localhost:5173>: под заголовком «Domino» появится статус `connected`. Сервер слушает `:3001`, клиент — `:5173` (запросы `/socket.io` Vite проксирует на сервер). Ctrl+C останавливает оба процесса.

## Как сыграть с другом

1. Откройте <http://localhost:5173>, выберите «Играем до» (51 / 101 / 151 очко, по умолчанию 101), «Костей в руке» (5 / 6 / 7, по умолчанию 7; базар = 28 − 2 × рука) и «Время на ход» (Выкл / 30 с / 60 с, по умолчанию 60 с; выбор запоминается в `localStorage` — `domino:matchTarget`, `domino:handSize`, `domino:turnSeconds`), введите имя и нажмите «Создать игру».
2. На экране «Ожидаем соперника…» нажмите «Скопировать» и отправьте ссылку вида `http://localhost:5173/?room=ABC234` другу.
3. Друг открывает ссылку, вводит имя и жмёт «Войти» — у обоих открывается игровой стол: цепочка в центре, своя рука снизу, рука соперника рубашкой сверху, «Базар: N» и индикатор «Ваш ход» / «Ход соперника».
4. Ходите кликом (или тапом) по подсвеченной кости — подсвечены только те, что можно сыграть; первый ход — старшим дублем. Если кость подходит к обоим концам цепочки, появятся кнопки «◀ сюда» / «сюда ▶» — выберите конец (Esc или повторный клик отменяют выбор).
5. Нет хода костью — активна «Взять из базара» (ход остаётся за вами, можно добирать подряд); базар пуст — «Пропустить».
6. Когда раунд закончился, у обоих появляется экран итогов: кто выиграл и почему (домино / рыба / ничья), обе руки лицом с суммами очков и начисленные очки. Над столом всё время видно табло матча «Аня 34 : 12 Боб · до 101 · Раунд 3».
7. Матч идёт до выбранной цели (по умолчанию 101 очко); настройки комнаты не меняются до её закрытия — ни на следующий раунд, ни на реванш. Второй игрок видит их на экране приглашения ещё до «Войти» («Матч до 51 · 5 костей в руке · ход 60 с»), оба — на табло («до 51», при руке ≠ 7 — «по 5 костей»). Дальше: нажмите «Следующий раунд» — новый раунд начнётся, когда нажмут оба (у нажавшего — «Ждём соперника…», у другого — «Соперник готов»). Когда у кого-то ≥ цели, показывается победитель матча и кнопка «Реванш» — новый матч 0 : 0 в той же комнате. Для быстрой проверки конца матча запустите `MATCH_TARGET=20 npm run dev` — значение 20 появится среди вариантов («20 (тест)») и будет выбрано по умолчанию.
8. Обрыв связи, F5 или даже закрытая вкладка не выкидывают из партии: место держится за **браузером** — токен лежит в `localStorage` (`domino:sessions`, по коду комнаты). Откройте ту же ссылку-приглашение в том же браузере — вернётесь на своё место с той же рукой, столом, счётом и очередью хода, а не войдёте «третьим игроком». При обрыве сокета клиент переподключается сам и показывает плашку «Переподключение…».
9. Пока соперник отключён, у вас плашка «Соперник отключился, ждём… mm:ss» с обратным отсчётом. Если он не вернулся за `RECONNECT_TIMEOUT` (по умолчанию 2 минуты), ему засчитывается техническое поражение в матче, а у вас — экран «Победа! Соперник не вернулся в игру» и кнопка «На главную». Для быстрой проверки: `RECONNECT_TIMEOUT=15000 npm run dev`.
10. Стол «живой»: сыгранная кость прилетает из руки (своей или соперника) на свой конец цепочки, добранная — вылетает из «Базар: N»; звучат стук кости, добор, сигнал «Ваш ход» (только когда ход перешёл к вам) и конец раунда. Кнопка 🔊/🔇 справа от заголовка включает/выключает звук, выбор запоминается (`localStorage['domino:sound']`). Звук по умолчанию включён, но браузеры разрешают его только после первого клика/нажатия клавиши на странице. При `prefers-reduced-motion: reduce` (настройки ОС или DevTools → Rendering) анимации не проигрываются, стол обновляется мгновенно; принудительно выключить анимации — `?fx=off` в адресе.
11. Таймер хода: у игрока, чей ход, идёт обратный отсчёт `mm:ss` (последние 10 с — красным и с пульсацией), в табло — «· ход 60 с». Время вышло — сервер ходит сам: самой тяжёлой подходящей костью; нечем — добирает из базара до подходящей кости и играет её; базар пуст — пропуск. Добор время не продлевает, смена хода запускает таймер соперника заново. Пока кто-то из игроков отключён, таймер стоит (`⏸ mm:ss`) и после возвращения продолжается с остатка. «Выкл» — таймера нет. Настройка действует до конца жизни комнаты (включая следующие раунды и реванш); второй игрок принимает её как есть.
12. Реакции: кнопка 💬 рядом с «Взять из базара»/«Пропустить» (на экране итогов — под итогами) открывает панель с фиксированным набором — 👍 😂 😮 😡 🎉 и фразы «Ну ты даёшь», «Рыба!», «Ходи уже», «Хорошая игра». Выбранная реакция ~3 с видна «облачком» у обоих: у соперника — под рубашками его руки, у себя — над своей рукой. Не чаще одной реакции в 2 с (кнопки на это время неактивны); свободного текста нет — сервер принимает только id из набора.

Ссылка с `localhost` работает только на этой машине. Проверить «на себе» можно в **двух разных браузерах** или в обычном окне + окне инкогнито: вкладки одного браузера — это один и тот же игрок (вторая вкладка заберёт место, первая покажет «Игра открыта в другой вкладке»). Для игры по сети откройте клиент по IP/имени хоста, доступному другу (например, `npm run dev -w @domino/client -- --host` и `http://<ваш-IP>:5173`), — ссылка строится из текущего адреса страницы. В проде (см. «Деплой») ссылка-приглашение строится от `PUBLIC_URL` сервера, например `https://domino-testdenis.fly.dev/?room=ABC234`. Спеки: лобби — [`docs/specs/spec-5.md`](docs/specs/spec-5.md), игровой стол — [`docs/specs/spec-6.md`](docs/specs/spec-6.md), итоги раунда и матч — [`docs/specs/spec-7.md`](docs/specs/spec-7.md), деплой — [`docs/specs/spec-8.md`](docs/specs/spec-8.md), переподключение — [`docs/specs/spec-9.md`](docs/specs/spec-9.md), звуки и анимации — [`docs/specs/spec-10.md`](docs/specs/spec-10.md), таймер хода — [`docs/specs/spec-11.md`](docs/specs/spec-11.md), реакции — [`docs/specs/spec-12.md`](docs/specs/spec-12.md), полировка UI и мобильная вёрстка — [`docs/specs/spec-13.md`](docs/specs/spec-13.md), настройки комнаты (цель матча, размер руки) — [`docs/specs/spec-14.md`](docs/specs/spec-14.md).

| `npm run screens`      | скриншоты ключевых экранов 360/1280 px в `docs/screens/` (Playwright, свой сервер с `MATCH_TARGET=30`; остановите `npm run dev` перед запуском) |

Перед первым запуском e2e установите браузер:

```bash
npx playwright install chromium
```

Все e2e-контексты эмулируют `prefers-reduced-motion: reduce` (`reducedMotion` в `playwright.config.ts` и `newPlayer`), поэтому полёты костей им не мешают; `e2e/fx.spec.ts` (E16–E18) проверяет кнопку звука на 360 px и ходы с включёнными анимациями (`newPlayer(browser, { reducedMotion: 'no-preference' })`).

Если `npm run dev` уже запущен, Playwright использует его (`reuseExistingServer`) — тогда поднимите его с тем же коротким таймаутом, иначе X17 будет ждать 2 минуты и упадёт, а в E19–E22 не будет варианта «3 с»: `RECONNECT_TIMEOUT=8000 TURN_TIMER_TEST_SECONDS=3 npm run dev`.

## Структура

- `shared/` (`@domino/shared`) — общие типы и правила раунда (`shared/src/rules`). Без шага сборки: пакеты импортируют исходники.
- `server/` (`@domino/server`) — HTTP + Socket.IO сервер; проверяет каждое действие игрока.
- `client/` (`@domino/client`) — React-приложение; только отображает состояние и отправляет намерения. Лобби (экраны, ссылка-приглашение, авто-возврат в комнату) — `client/src/lobby`; игровой стол — `client/src/game` (подсветка и кнопки берутся только из `legalMoves`, которые прислал сервер); анимации — `client/src/fx` (события стола выводятся из разницы двух `room:state`, полёты — Web Animations API); звук — `client/src/sound` (Web Audio, кнопка 🔊/🔇); реакции — `client/src/reactions` (панель 💬 и облачки; набор — только `shared/src/reactions.ts`).
- `Dockerfile`, `.dockerignore`, `fly.toml` — production-образ и конфиг Fly.io; раздачу статики делает `server/src/static.ts`, env читает `server/src/config.ts`.
- `e2e/` — сценарии Playwright (`connect.spec.ts` — E1–E2, `lobby.spec.ts` — E3–E7: два игрока встречаются в одной комнате, `game.spec.ts` — E8–E11: игроки делают ходы, мобильная ширина, F5, `match.spec.ts` — E12–E15: раунд до конца, итоги, следующий раунд, `reconnect.spec.ts` — X16–X19: возврат после закрытия браузера, победа по таймауту, повторное открытие ссылки, обрыв сети, `fx.spec.ts` — E16–E18: кнопка звука на 360 px, ходы с анимациями, нет ошибок автоплея, `turn-timer.spec.ts` — E19–E22: таймер хода, `reactions.spec.ts` — E23–E26: A отправляет реакцию — B её видит, фраза, анти-спам, 360 px, `layout.spec.ts` — E27–E32: вёрстка на 360/390/768/1280 px (нет горизонтального скролла, кнопки ≥ 44 px, переносы длинных имён и цепочки), облачко соперника не закрывает стол, без связи нет подсветки «Ваш ход», `settings.spec.ts` — E-S1–E-S4: настройки комнаты (цель 51 видна до входа и на табло, рука 5 и базар 18, значения по умолчанию, мёртвая ссылка); `screens.spec.ts` — S1: скриншоты для `npm run screens`, в основной прогон не входит; общие хелперы — `helpers.ts`, в т.ч. `checkLayout`). Каждый игрок — отдельный контекст браузера (`newPlayer`), т.к. место держится за `localStorage`.

Сервер — источник истины. Контракт событий Socket.IO описан в одном месте — `shared/src/protocol.ts` — и типизирует обе стороны: переименование события ломает `typecheck` и на сервере, и на клиенте.

## Правила раунда (`shared/src/rules`)

Чистые детерминированные функции без сети и UI; состояние раунда (`RoundState`) — plain JSON. Спека: [`docs/specs/spec-3.md`](docs/specs/spec-3.md).

```ts
import { startRound, getLegalMoves, applyMove, toPlayerView } from '@domino/shared';

let state = startRound({ seed: 42 }); // перемешивание mulberry32 + Fisher–Yates, раздача 7/7/14
// startRound({ seed: 42, handSize: 5 }) — раздача 5/5/18 (spec-14: handSize ∈ 5 / 6 / 7)
const [move] = getLegalMoves(state); // первый ход — всегда старший дубль
const result = applyMove(state, state.currentPlayer, move!); // { ok: true, state } | { ok: false, error }
if (result.ok) state = result.state;
toPlayerView(state, 0); // то, что можно показать игроку 0: без костей соперника и базара
```

Тесты правил: `npx vitest run --project shared` (в названиях тестов — ID правил `R1:`…`R15:`).

## Протокол комнат

Сервер держит в памяти комнаты на двоих: в каждой — настройки (цель матча, размер руки, время на ход — [`spec-14`](docs/specs/spec-14.md)), матч и текущий раунд ([`spec-7`](docs/specs/spec-7.md)). Типы событий — `shared/src/protocol.ts`, спека: [`docs/specs/spec-4.md`](docs/specs/spec-4.md). Ошибки приходят только в ack: `{ ok: false, error }`.

| Событие         | Направление | Payload                                           | Ответ / смысл                                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------- | ----------- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `room:create`   | C → S       | `{ name, turnSeconds?, matchTarget?, handSize? }` | ack `{ ok, roomId, seat: 0, playerToken }`; комната ждёт второго игрока. `turnSeconds` — время на ход, с, из `server:hello.turnSecondsOptions` (нет — 60); `matchTarget` — из `server:hello.matchTargetOptions` (нет — `MATCH_TARGET` ?? 101); `handSize` — 5 / 6 / 7 (нет — 7). Значение не из списка — `INVALID_PAYLOAD`                                                                                     |
| `room:info`     | C → S       | `{ roomId }`                                      | ack `{ ok, roomId, settings: { matchTarget, handSize, turnSeconds } }`; настройки комнаты до входа, без побочных эффектов. Ошибки: `INVALID_PAYLOAD`, `ROOM_NOT_FOUND`                                                                                                                                                                                                                                         |
| `room:join`     | C → S       | `{ roomId, name }`                                | ack `{ ok, roomId, seat: 1, playerToken }`; раунд стартует сразу                                                                                                                                                                                                                                                                                                                                               |
| `room:rejoin`   | C → S       | `{ roomId, playerToken }`                         | ack `{ ok, roomId, seat }`; возврат на место до `RECONNECT_TIMEOUT`. Чужой/выдуманный токен — `INVALID_TOKEN`, после техпоражения — `ROOM_NOT_FOUND`                                                                                                                                                                                                                                                           |
| `game:move`     | C → S       | `{ move }` (`play/draw/pass`)                     | ack `{ ok }` или код ошибки правил (`NOT_YOUR_TURN`, `TILE_DOES_NOT_FIT`, …)                                                                                                                                                                                                                                                                                                                                   |
| `game:ready`    | C → S       | `{}`                                              | «Следующий раунд» / «Реванш»; когда готовы оба — новый раунд (матч). Ошибки: `ROUND_NOT_FINISHED`, `GAME_NOT_STARTED`, `NOT_IN_ROOM`                                                                                                                                                                                                                                                                           |
| `room:state`    | S → C       | `RoomStatePayload`                                | после каждого изменения — каждому игроку свой вид: свои кости, у соперника число (рука соперника — только после конца раунда), счёт `match`; `players[].reconnectRemainingMs` — сколько мс ещё ждём отключённого (`null` у подключённого); `match.forfeit` — место, проигравшее техпоражением (тогда `phase: 'finished'`); `turnSeconds` и `turnTimer { seat, remainingMs, paused }` (`null` — таймер не идёт) |
| `game:react`    | C → S       | `{ reactionId }`                                  | реакция из фиксированного набора `REACTIONS` (`shared/src/reactions.ts`); ack `{ ok }` или `INVALID_PAYLOAD` (payload не объект), `UNKNOWN_REACTION` (id не из набора — в т.ч. эмодзи или произвольный текст), `GAME_NOT_STARTED` (ещё `waiting`), `NOT_IN_ROOM`, `TOO_FREQUENT` (чаще 1 раза в 2 с на место; переподключение кулдаун не сбрасывает)                                                           |
| `room:reaction` | S → C       | `{ seat, reactionId, seq }`                       | принятая реакция — обоим подключённым игрокам, включая отправителя; `room:state` не шлётся, отключённому не доставляется и не копится                                                                                                                                                                                                                                                                          |
| `room:closed`   | S → C       | `{ roomId, reason }`                              | `player_left` — соперник не вернулся, а победителя не назначить (комната ещё ждала второго, матч уже окончен или ушли оба); `replaced` — место заняла другая вкладка                                                                                                                                                                                                                                           |

Код комнаты — 6 символов (`A–Z`, `2–9` без `I O 0 1`), регистр при входе не важен. Отключившемуся игроку место держится `RECONNECT_TIMEOUT`; если он не вернулся, а соперник в сети и матч не окончен — отключившемуся засчитывается техническое поражение (`match.forfeit`, счёт не меняется), оставшийся получает финальный `room:state`, комната удаляется; иначе — `room:closed player_left`. Сервер пингует клиентов каждые 10 с (таймаут 5 с), так что пропажа сети без закрытия сокета обнаруживается ≤ 15 с. Комнаты живут только в памяти процесса.

`server:hello` (S → C) несёт `protocolVersion`, `serverTime`, `publicUrl?`, `turnSecondsOptions` (обычно `[0, 30, 60]`), `matchTargetOptions` (обычно `[51, 101, 151]`), `defaultMatchTarget` и `handSizeOptions` (`[5, 6, 7]`). `room:state` во всех фазах несёт настройки комнаты `turnSeconds`, `matchTarget`, `handSize`. Таймер хода держит сервер ([`spec-11`](docs/specs/spec-11.md)): по истечении он сам доигрывает ход (`pickAutoMove` из `shared`) и рассылает один `room:state`; отдельных «тиков» нет — клиент считает остаток сам.

Тесты: `npx vitest run --project server` (unit `U*`, комнаты `R*`, игра `G*`, отключения `D*`, матч `N*`, переподключение и техпоражение `X*` — `reconnect.test.ts`, таймер хода `T*` — `RoomManager.test.ts`, `turn-timer.test.ts`, реакции `RX*` — `RoomManager.test.ts`, `reactions.test.ts`, настройки комнаты `S*`/`SI-*` — `RoomManager.test.ts`, `settings.test.ts`).

## Переменные окружения сервера

| Переменная                | По умолчанию            | Назначение                                                                                                                    |
| ------------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `PORT`                    | `3001`                  | порт сервера                                                                                                                  |
| `HOST`                    | `0.0.0.0`               | интерфейс                                                                                                                     |
| `CORS_ORIGIN`             | `http://localhost:5173` | разрешённый origin клиента                                                                                                    |
| `RECONNECT_TIMEOUT`       | `120000`                | сколько ждать возвращения отключившегося игрока, мс (целое > 0); потом — техпоражение                                         |
| `MATCH_TARGET`            | `101`                   | цель матча по умолчанию (целое > 0); значение вне 51 / 101 / 151 добавляется в варианты выбора (для тестов)                   |
| `PUBLIC_URL`              | —                       | база ссылок-приглашений, напр. `https://domino-testdenis.fly.dev` (http/https, без пути); не задан — клиент берёт свой origin |
| `STATIC_DIR`              | —                       | каталог собранного клиента (в образе `/app/client/dist`); задан — сервер раздаёт клиент на своём порту                        |
| `TURN_TIMER_TEST_SECONDS` | —                       | **только для тестов**: добавляет к выбору времени на ход короткое значение, с (целое 1…29); в проде не задаётся               |

Невалидные `MATCH_TARGET` / `RECONNECT_TIMEOUT` / `PUBLIC_URL` / `STATIC_DIR` / `TURN_TIMER_TEST_SECONDS` (каталог без `index.html`) — процесс падает на старте с понятной ошибкой.

Проверка здоровья: `curl -s localhost:3001/healthz` → `{"status":"ok"}` (старый `/health` тоже работает).

## Запуск в Docker

Production-образ (`Dockerfile`, multi-stage, `node:22-alpine`): один процесс Node.js раздаёт собранный клиент и Socket.IO на одном порту `8080` — CORS не нужен. В образе только prod-зависимости сервера, процесс работает от пользователя `node`.

```bash
npm run docker:build   # docker build -t domino .
npm run docker:run     # docker run --rm -p 8080:8080 -e PUBLIC_URL=http://localhost:8080 domino
```

Откройте <http://localhost:8080> в двух разных браузерах (или обычном окне + инкогнито) и сыграйте партию, как описано выше. Другие настройки — через `-e`, например `docker run --rm -p 8080:8080 -e MATCH_TARGET=20 domino`. Статус healthcheck: `docker inspect --format '{{.State.Health.Status}}' <container>`.

Без Docker то же самое: `npm run build && STATIC_DIR=client/dist PORT=8080 npm start`.

## Деплой

Хостинг — [Fly.io](https://fly.io), конфиг — `fly.toml`: одна машина в регионе `fra`, WebSocket работает через `http_service` без доп. настроек, проверка здоровья — `GET /healthz`.

Один раз:

1. Установите [`flyctl`](https://fly.io/docs/flyctl/install/) и войдите: `fly auth login`.
2. Создайте приложение: `fly apps create domino-testdenis`. Если имя занято — выберите своё и замените `app` и `PUBLIC_URL` в `fly.toml`.
3. Первый деплой вручную: `fly deploy --ha=false` → игра доступна на `https://<app>.fly.dev`, ссылку-приглашение можно отправлять другу.
4. Создайте токен: `fly tokens create deploy -x 999999h` и добавьте его в GitHub: Settings → Secrets and variables → Actions → New repository secret `FLY_API_TOKEN`.
5. Дальше каждый push в `main` после зелёных `checks`, `e2e` и `docker` деплоится автоматически (job `deploy`). Без секрета job `deploy` завершается успешно с notice «Деплой пропущен» — CI не краснеет.

Ограничения: комнаты живут в памяти одной машины. Деплой, рестарт или авто-остановка машины (`auto_stop_machines`, когда никто не подключён) обрывают текущие партии. Не запускайте больше одной машины (`fly scale count` > 1): игроки одной комнаты окажутся на разных инстансах. Логи — `fly logs`.

## CI

GitHub Actions (`.github/workflows/ci.yml`) запускается на каждый pull request и на push в `main`:

- `checks` — `npm ci`, `lint`, `typecheck`, `test`, `build`;
- `e2e` — Playwright в Chromium (после `checks`); при падении отчёт сохраняется артефактом `playwright-report`;
- `docker` — сборка production-образа, запуск контейнера, проверка `/healthz`, пользователя `node` и отсутствия dev-зависимостей, e2e E1/E3/E4/E12 против контейнера (`E2E_BASE_URL=http://localhost:8080`);
- `deploy` — только на push в `main`, после `checks`, `e2e`, `docker`: `flyctl deploy --remote-only --ha=false`. Без секрета `FLY_API_TOKEN` — success с notice «Деплой пропущен».

Job'ы `checks`, `e2e`, `docker` стоит сделать обязательными для merge в настройках branch protection.

E2E против уже запущенного сервера (например, контейнера): `E2E_BASE_URL=http://localhost:8080 npm run test:e2e` — Playwright тогда не поднимает `npm run dev`.
