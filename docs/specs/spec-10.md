## 1. Цель

Сделать стол «живым» без изменения правил и протокола:

1. **Анимации:** сыгранная кость плавно летит из руки (своей) или от руки соперника на свой конец цепочки; добор из базара — короткий «вылет» кости из счётчика базара в руку.
2. **Звуки:** стук кости при ходе, звук добора, сигнал «Ваш ход» (только при переходе хода к игроку), звук конца раунда.
3. **Кнопка звука** вкл/выкл, состояние в `localStorage`; по умолчанию включён, но ничего не звучит до первого взаимодействия пользователя (политика автоплея).
4. `prefers-reduced-motion: reduce` → анимации мгновенные (не запускаются).
5. Звуковые файлы — свои или CC0, источник в README.

Всё — чисто клиентская «косметика»: что произошло, клиент выводит из разницы двух последовательных `room:state` (сервер остаётся источником истины, состояние на экране всегда = последний `room:state`; анимация только визуально догоняет его).

## 3. Нормативные правила

### 3.1 События стола (diff двух `PlayerView`)

Чистая функция `diffTable(prev: PlayerView | null, next: PlayerView): TableEvent[]`.

```ts
type Who = 'me' | 'opponent';
type TableEvent =
  | { type: 'play'; who: Who; tile: Tile; end: End; boardIndex: number } // boardIndex — индекс в next.board
  | { type: 'draw'; who: Who }
  | { type: 'turn' } // ход перешёл ко мне
  | { type: 'roundEnd' };
```

| ID  | Правило                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | `prev === null` (первый `room:state` после монтирования, F5, `room:rejoin`) → `[]`.                                                                                                                                                                                                                                                                                                                                                                                                   |
| A2  | Новый раунд (`prev.status === 'finished' && next.status === 'playing'`, или `next.board.length < prev.board.length`) → `[]`.                                                                                                                                                                                                                                                                                                                                                          |
| A3  | **play:** `next.board.length === prev.board.length + 1`. `end = 'left'`, если `next.board[1…]` совпадает с `prev.board` (новая кость — `next.board[0]`, `boardIndex 0`), иначе `'right'` (`boardIndex = next.board.length - 1`); первая кость на пустой стол — `end 'right'`, `boardIndex 0`. `who = 'me'`, если `next.hand.length === prev.hand.length - 1`; `'opponent'`, если `next.opponentHandCount === prev.opponentHandCount - 1`. `tile` — `[left,right]` новой `PlacedTile`. |
| A4  | **draw:** доска не изменилась, `next.boneyardCount === prev.boneyardCount - 1`; `who` — чья рука выросла на 1.                                                                                                                                                                                                                                                                                                                                                                        |
| A5  | **turn:** `next.status === 'playing'`, `prev.status === 'playing'`, `prev.currentPlayer !== you`, `next.currentPlayer === you`. Свой добор (ход остаётся у меня) и старт нового раунда (A2) сигнал **не** дают.                                                                                                                                                                                                                                                                       |
| A6  | **roundEnd:** `prev.status === 'playing' && next.status === 'finished'`. Может идти вместе с `play` (последняя кость).                                                                                                                                                                                                                                                                                                                                                                |
| A7  | Любое иное или «несколько шагов за раз» (доска +2, базар −2, рука и доска одновременно не сходятся с A3/A4 — например, пропущенные состояния при обрыве) → `[]` для play/draw (тихая синхронизация); A5/A6 проверяются независимо. `pass` событий не даёт.                                                                                                                                                                                                                            |
| A8  | Порядок в массиве: `play` / `draw`, затем `roundEnd`, затем `turn`.                                                                                                                                                                                                                                                                                                                                                                                                                   |

### 3.2 Анимации

| ID  | Правило                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AN1 | Техника — FLIP через Web Animations API (`element.animate`), **без новых зависимостей**. DOM сразу рендерит итоговое состояние; анимируется только `transform`/`opacity` целевого элемента «из точки источника в своё место».                                                                                                                                                                                                                                                                                               |
| AN2 | **play, me:** источник — прямоугольник `hand-tile-*` этой кости, запомненный на предыдущем коммите; цель — `board-tile-${boardIndex}`. **play, opponent:** источник — последний `opponent-tile` предыдущего рендера (если рука была пуста/нет элемента — центр `opponent-hand`). Длительность **250 мс**, `ease-out`, keyframes `translate(dx,dy) scale(s) → none`, где `s` = отношение ширины источника к цели (кость в руке вертикальная, на столе может быть горизонтальной — допускается без поворота, только масштаб). |
| AN3 | **draw, me:** цель — новая кость в `my-hand` (та, которой не было в `prev.hand`), источник — `boneyard-count`; **draw, opponent:** цель — последний `opponent-tile`. Длительность **180 мс**, `translate + opacity 0 → 1`.                                                                                                                                                                                                                                                                                                  |
| AN4 | Прямоугольники источников снимаются в `useLayoutEffect` на каждом коммите стола (≤ 28 элементов, `getBoundingClientRect`) и хранятся в `ref`; анимация запускается в `useLayoutEffect` следующего коммита — до отрисовки кадра, без мигания.                                                                                                                                                                                                                                                                                |
| AN5 | Анимация **не блокирует ввод** и не задерживает обновление состояния: элементы кликабельны сразу, следующий `room:state` во время полёта — текущая анимация `finish()`-ится, новая стартует от актуальных координат. Во время полёта у цели `pointer-events` не меняются.                                                                                                                                                                                                                                                   |
| AN6 | Нет `Element.prototype.animate`, элемент не найден, источник вне вьюпорта (rect нулевой) → анимация пропускается без ошибки.                                                                                                                                                                                                                                                                                                                                                                                                |
| AN7 | `matchMedia('(prefers-reduced-motion: reduce)').matches` → анимации не запускаются вовсе (мгновенно). Подписка на `change` — переключение в ОС действует без перезагрузки. CSS-переходы, если добавляются, оборачиваются в `@media (prefers-reduced-motion: no-preference)`.                                                                                                                                                                                                                                                |
| AN8 | Новых `data-testid` на летящие элементы нет (анимируется сам целевой элемент), значит DOM/локаторы e2e не меняются.                                                                                                                                                                                                                                                                                                                                                                                                         |

### 3.3 Звуки

| ID  | Правило                                                                                                                                                                                                                                                                                                                              |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| S1  | Четыре звука: `tile` (стук кости), `draw` (добор), `turn` (сигнал «Ваш ход»), `roundEnd` (конец раунда). Файлы `client/src/sound/assets/{tile,draw,turn,round-end}.mp3`, импортируются через Vite (`import url from './assets/tile.mp3'` → хешированный URL в `assets/`), каждый ≤ 40 КБ, ≤ 1,5 с, моно, нормализованы по громкости. |
| S2  | Маппинг событий: `play` (любой игрок) → `tile`; `draw` (любой) → `draw`; `turn` → `turn`; `roundEnd` → `roundEnd`. Если в одном diff `roundEnd` — `turn` не играется (по A5 его и так нет). `tile`/`draw` — сразу; `roundEnd` и `turn` — с задержкой **250 мс** (после стука/полёта).                                                |
| S3  | Воспроизведение через Web Audio API: один `AudioContext` на приложение, буферы декодируются лениво при первой разблокировке, каждый звук — новый `AudioBufferSourceNode` (наложение разрешено), общий `GainNode` 0.6.                                                                                                                |
| S4  | **Автоплей:** `AudioContext` создаётся/`resume()`-ится только в обработчике первого `pointerdown` или `keydown` на `window` (`{ once: true, capture: true }`). До этого — звуки **отбрасываются** (не копятся в очередь).                                                                                                            |
| S5  | Звук выключен → `play()` — no-op (контекст можно не создавать). Состояние в `localStorage['domino:sound']` = `'on' \| 'off'`; отсутствует/мусор/исключение доступа → `'on'`. Запись — при каждом переключении, ошибки записи глотаются.                                                                                              |
| S6  | Нет `AudioContext` (`window.AudioContext ?? window.webkitAudioContext`), ошибка загрузки/декодирования → тихий no-op, `console.warn` один раз, без UI-ошибок.                                                                                                                                                                        |
| S7  | `prefers-reduced-motion` на звук **не** влияет. Звуки в фоне (вкладка скрыта) не подавляются специально — браузер решает сам.                                                                                                                                                                                                        |

### 4.4 Тестовый режим и e2e

- `e2e/helpers.ts` → `newPlayer`: в `browser.newContext({...})` добавить `reducedMotion: 'reduce'` (по умолчанию для всех e2e; параметр `PlayerOptions.reducedMotion?: 'reduce' \| 'no-preference'` для E17). В `playwright.config.ts` → `use.reducedMotion: 'reduce'` для тестов, использующих `page` напрямую (E1–E2).
- Дополнительно — query-параметр **`?fx=off`** (читается один раз при загрузке в `motionDisabled()`): отключает анимации независимо от ОС. Нужен для ручной отладки и прогона против внешнего `E2E_BASE_URL`; e2e им не пользуются (хватает `reducedMotion`).
- Звук в e2e не проверяется на слух; Chromium headless без жеста не разблокирует аудио — ошибок быть не должно (S4/S6).

## 5. Протокол (Socket.IO)

**Не затрагивается.** Новых событий и полей нет; `PROTOCOL_VERSION` без изменений. События стола выводятся на клиенте из `room:state` (A1–A8).

## 6. Критерии готовности

1. `npm run lint`, `npm run typecheck`, `npm test`, `npm run test:e2e` зелёные; CI (`checks`, `e2e`, docker) проходит; новых npm-зависимостей нет.
2. Свой ход: кость визуально перелетает из руки на нужный конец цепочки за ~250 мс; ход соперника — от его руки (рубашек) к нужному концу. Проверка вручную в двух браузерах + unit F*.
3. Добор (свой и соперника): короткий вылет от «Базар: N» к руке, ~180 мс.
4. При `prefers-reduced-motion: reduce` (DevTools → Rendering → Emulate) `Element.animate` не вызывается ни разу; стол обновляется мгновенно.
5. Звуки: стук на каждый ход любого игрока, звук добора, сигнал «Ваш ход» **только** когда ход перешёл от соперника ко мне (не при своём доборе, не при F5/rejoin, не на старте раунда), звук конца раунда один раз на раунд.
6. До первого клика/нажатия клавиши на странице ни один звук не воспроизводится и в консоли нет ошибок автоплея (`NotAllowedError`).
7. Кнопка `sound-toggle` видна на лобби и столе, переключает 🔊/🔇 и `aria-pressed`; после F5 состояние сохраняется (`localStorage['domino:sound']`); при «выкл» звуков нет.
8. На 360×640: кнопка во вьюпорте, ≥ 44×44 px, нет горизонтальной прокрутки, кнопка нажимается.
9. Все существующие e2e (E1–E15, X16–X19) проходят без изменения сценариев.
10. `.mp3` отдаётся собранным сервером с `Content-Type: audio/mpeg`; в README есть таблица источников звуков с лицензией CC0 (или «собственный»).
11. Отсутствие `AudioContext`/`animate`/`matchMedia` не ломает приложение (jsdom-тесты без моков зелёные).

## 10. Допущения

1. **События выводятся на клиенте** из diff `PlayerView` (A1–A8), а не новым полем протокола: карточка с тегом `client`, а `room:state` после каждого действия однозначно описывает один шаг. Если когда-нибудь diff станет неоднозначным — добавить `lastMove` в протокол отдельной задачей.
2. **Сигнал «Ваш ход»** — только при смене `currentPlayer` с соперника на меня внутри раунда; на старте нового раунда, после F5/rejoin и после собственного добора не звучит.
3. **Без новых зависимостей**: Web Animations API + Web Audio API достаточно; альтернативы (framer-motion, howler) отклонены ради размера бандла.
4. **Тестовый режим** — через эмуляцию `prefers-reduced-motion` в Playwright (`reducedMotion: 'reduce'`) — это одновременно проверяет требование карточки; плюс `?fx=off` для ручной/внешней проверки.
5. **Формат mp3** — поддерживается всеми целевыми браузерами (включая iOS Safari); одного формата достаточно.
6. **Звук по умолчанию «вкл»**, но неслышен до первого `pointerdown`/`keydown`; звуки до разблокировки не копятся.
7. Кнопка звука глобальная (в шапке `App`), а не только на столе — так её видно и в лобби, где проверяется 360 px.
8. Базовая ветка — `task-9-reconnect` (там `newPlayer`, `static.ts`, localStorage-хранилище); если #8/#9 ещё не смёржены к началу работ — ребейз после merge.
9. Конкретные файлы Kenney — рекомендация; финальный выбор за разработчиком при соблюдении S1 и указании источника в README.
